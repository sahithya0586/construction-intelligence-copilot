## 📌 Overview

**Construction Intelligence Copilot** is an AI-powered construction information assistant that combines **document-based Retrieval-Augmented Generation (RAG)** with **construction-site image understanding**.

The system allows users to ask natural-language questions about construction documents and construction-site images. It retrieves relevant evidence from the knowledge base and uses **Google Gemini** to generate a grounded response.

The project currently supports:

- 📄 Construction document/PDF retrieval
- 🖼️ Construction-site image understanding
- 🔎 Semantic similarity search
- 🧠 Sentence Transformer embeddings
- 🗄️ ChromaDB vector storage
- 👁️ Gemini vision-language analysis
- 🤖 Gemini-based answer generation
- 💬 Interactive Streamlit chat interface
- 📚 Evidence-based responses

---

## 🎯 Problem Statement

Construction projects generate large amounts of information through:

- Safety documents
- Construction guidelines
- Project reports
- Site photographs
- Inspection information
- Structural information
- Construction activities
- Safety observations

Finding relevant information manually from these sources can be time-consuming.

Traditional keyword-based search also has limitations when the required information is contained in images rather than text.

This project addresses the problem by combining:

**Document Retrieval + Image Understanding + Semantic Search + Generative AI**

into a single construction intelligence assistant.

---

## 💡 Key Features

### 📄 1. Document-Based RAG

Construction PDFs are processed and divided into meaningful chunks.

The system:

1. Loads PDF documents
2. Extracts text
3. Splits the text into chunks
4. Generates embeddings
5. Stores embeddings in ChromaDB
6. Retrieves relevant chunks for user queries

---

### 🖼️ 2. Construction-Site Image Understanding

Construction-site images are analyzed using Google's Gemini vision-language model.

The system extracts structured information such as:

- Construction phase
- Construction activities
- Materials
- Equipment
- Structural elements
- Workers
- Safety hazards
- Site conditions
- Progress indicators

Example:

```text
Construction Phase:
Superstructure

Activities:
- Concrete work
- Formwork
- Reinforcement work

Materials:
- Reinforcement steel
- Concrete
- Plywood

Safety Hazards:
- Missing edge protection
- Exposed reinforcement bars
- Uneven construction surfaces
```

---

## 🔎 3. Semantic Search

The system uses **Sentence Transformers** to convert text into numerical vector representations called **embeddings**.

These embeddings allow the system to find information based on **meaning and semantic similarity**, rather than relying only on exact keyword matches.

For example, a query such as:

```text
What safety risks are visible at the construction site?
```

can retrieve relevant information describing:

- Missing edge protection
- Exposed reinforcement bars
- Uneven surfaces
- Scaffolding conditions

even when the exact words in the query are not present in the stored information.

---

## 🗄️ 4. ChromaDB Vector Storage

The generated embeddings are stored in **ChromaDB**, which acts as the project's vector database.

The database stores both:

- 📄 Document-derived knowledge
- 🖼️ Image-derived knowledge

Each stored record also contains metadata such as:

- Source type
- File name
- Page number for documents
- Chunk information
- Image filename
- Construction phase

This metadata helps the system identify where retrieved information originated.

---

## 🔗 5. Multimodal Retrieval

The system supports retrieval from different types of construction information.

### Document Query

For questions related to construction guidelines, standards, procedures, or safety documents, the system retrieves relevant PDF content.

### Image Query

For questions about what is visible in a construction image, the system retrieves image analysis generated by Gemini.

### Mixed Query

For questions requiring both visual evidence and document knowledge, the system retrieves information from both sources.

For example:

```text
What safety hazards are visible in this construction site,
and what safety practices should be followed?
```

The system separates:

**Visual Evidence**

→ Information identified from the construction image.

**Document Evidence**

→ Relevant safety information retrieved from construction documents.

This helps keep the generated answer grounded in the appropriate source.

---

## 🤖 6. Grounded Answer Generation

After retrieving relevant evidence, the system sends the retrieved context to **Google Gemini**.

Gemini generates the final response using the retrieved evidence as context.

The system is designed to:

- Use retrieved evidence
- Avoid unsupported claims
- Distinguish image observations from document recommendations
- Provide concise construction-related answers

The basic flow is:

```text
User Question
      ↓
Query Classification
      ↓
Semantic Retrieval
      ↓
Relevant Evidence
      ↓
Context Construction
      ↓
Google Gemini
      ↓
Grounded Answer
```

# 🔄 RAG Workflow

The complete pipeline follows these stages:

### Step 1 — Data Ingestion

PDF documents and construction-site images are collected and stored in the project's data directory.

### Step 2 — Document Processing

PDF text is extracted and divided into smaller chunks for efficient retrieval.

### Step 3 — Image Analysis

Construction images are analyzed using Gemini's vision-language capabilities.

The analysis produces structured information about the construction scene, including construction phase, activities, materials, equipment, workers, structural elements, hazards, site conditions, and progress indicators.

### Step 4 — Embedding Generation

Text chunks and image descriptions are converted into vector embeddings using a Sentence Transformer model.

### Step 5 — Vector Storage

The embeddings and associated metadata are stored in ChromaDB.

### Step 6 — Query Processing

When a user asks a question, the system determines whether the query requires:

- Document evidence
- Image evidence
- Or both

### Step 7 — Semantic Retrieval

The query is converted into an embedding and compared with stored embeddings.

Relevant records are retrieved from ChromaDB.

### Step 8 — Context Construction

The retrieved information is organized into context for the language model.

### Step 9 — Answer Generation

Google Gemini uses the retrieved context to generate the final response.

# 🧠 How the Multimodal RAG Works

The project uses a two-stage approach for construction images.

### Stage 1 — Vision Understanding

Gemini analyzes the construction image and converts visual information into structured text.

```text
Image
  ↓
Gemini Vision
  ↓
Construction Description
  ↓
Structured Metadata
```

The generated description can contain information about:

- Construction phase
- Activities
- Materials
- Equipment
- Structural elements
- Workers
- Safety hazards
- Site conditions
- Progress indicators

### Stage 2 — Vector Retrieval

The generated image description is converted into an embedding.

```text
Image Description
       ↓
Sentence Transformer
       ↓
Vector Embedding
       ↓
ChromaDB
```

When a user asks an image-related question, the query is also converted into an embedding.

ChromaDB then retrieves semantically similar image records.

This allows the system to answer questions about construction images using the image analysis stored in the knowledge base.

# 📚 Evidence Grounding

The system separates retrieved information according to its source.

### Image Evidence

Contains observations generated from construction-site images.

Examples:

- Visible workers
- Scaffolding
- Construction materials
- Structural elements
- Visible hazards
- Site conditions

### Document Evidence

Contains information retrieved from construction documents.

Examples:

- Safety procedures
- Inspection recommendations
- Safety practices
- Construction guidelines
- Hazard-control information

This separation helps the system distinguish between:

**What is visible**

and

**What the documents recommend.**

# 📈 Example of Evidence-Based Reasoning

Suppose the user asks:

```text
What hazards are visible at the construction site
and what safety practices should be followed?
```

The system handles the question in two parts.

### Part 1 — Visual Evidence

The image retrieval component can identify observations such as:

```text

- Material debris
- Scaffolding

```

### Part 2 — Document Evidence

The document retrieval component retrieves relevant construction safety information.

The final response is generated using both sources.

This architecture allows the system to distinguish between:

```text
OBSERVED IN IMAGE
        +
SUPPORTED BY DOCUMENT
        =
GROUNDED RESPONSE
```
